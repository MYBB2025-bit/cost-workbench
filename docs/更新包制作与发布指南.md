# 造价驻场工作台 · 更新包制作与发布指南

> 适用版本：GX1.0.0.1 及之后
> 适用对象：打包发布人员 / 现场驻场工程师

本指南说明如何把「造价驻场工作台」的新版本，打包成用户可直接使用的**更新包**，以及如何安全地发布、更新、回滚。

---

## 一、设计原则：程序 / 配置 / 数据 三者分离

为避免更新程序时破坏用户已填写的资料，程序、配置、数据分别存放：

```
造价驻场工作台/
├── 造价驻场工作台.exe        ← 启动器（程序入口）
├── cost-workbench.html       ← 主程序（可独立替换，本身不含用户数据）
├── data/                     ← 用户专属目录（更新程序时绝不触碰）
│   ├── user-data.json        ← 业务数据：项目、结算、收方签证、进度款、联系人…
│   ├── config.json           ← 用户配置：阶段、内业类别、AI 配置、备份设置…
│   └── version.json           ← 已应用版本记录
└── cost-workbench.html.bak.* ← 旧版快照（手动补丁或更新失败时生成）
```

- **浏览器里打开 HTML**：数据存在浏览器 `localStorage`，仅用于临时试用，不持久化。
- **双击 EXE**：数据自动落到 `data/` 目录，更新程序不会影响这两个文件。

---

## 二、版本号规则

统一以 `GX` 开头，四段式：

```
GX <主版本>.<次版本>.<修订>.<构建>
例：GX1.0.0.1  →  GX1.0.0.2  →  GX1.1.0.0
```

- 主版本：重大架构调整
- 次版本：较大功能新增
- 修订：功能小改 / 问题修复
- 构建：日常补丁累积

**只有 `update_包` 的版本号大于 `data/version.json` 里记录的版本，EXE 才会在启动时自动应用。**

---

## 三、更新包格式

一个更新包就是一个 zip，文件名必须叫 `update_GXx.x.x.x.zip`：

```
update_GX1.0.0.2.zip
├── cost-workbench.html       ← 新主程序（必须）
├── version.txt               ← 内容仅一行：GX1.0.0.2（必须）
└── manifest.json             ← 可选，写 sha256 校验（强烈建议发布时带上）
```

`manifest.json` 示例：

```json
{
  "version": "GX1.0.0.2",
  "files": {
    "cost-workbench.html": { "sha256": "填新 html 的 sha256 摘要" }
  }
}
```

## 四、制作方法

### 方法一：手动制作（适合偶尔发版）

1. 拿到新的 `cost-workbench.html`（已通过校验）。
2. 新建一个文件夹，把 `cost-workbench.html` 放进去。
3. 在同文件夹新建 `version.txt`，内容写新版本号（如 `GX1.0.0.2`）。
4. 选中这两个文件 → 右键 →「发送到 / 压缩(zipped)文件夹」。
5. 把生成的 zip 改名为 `update_GX1.0.0.2.zip`。

> 可选：用任意 sha256 工具算出 `cost-workbench.html` 的摘要，按第三节写进 `manifest.json` 一起压进去。

### 方法二：用脚本一键生成（推荐发布人员使用）

把 `build_exe/make_update.py` 与新 `cost-workbench.html` 放在同目录，运行：

```bash
python make_update.py --version GX1.0.0.2 --html cost-workbench.html
```

脚本会自动：
- 生成 `version.txt`
- 计算 `cost-workbench.html` 的 sha256 并生成 `manifest.json`
- 打包成 `update_GX1.0.0.2.zip`

（双击方式：直接运行 `make_update.py`，按提示输入版本号即可。）

## 五、发布给用户

把生成的 `update_GX1.0.0.2.zip` 通过微信 / 邮件 / U 盘交给用户，**只需这一个文件**。

不需要发 EXE，也不需要发 `data/` 目录。

---

## 六、用户端更新（两种方式）

### 方式 A：自动更新（推荐）

1. 用户把 `update_GX1.0.0.2.zip` 放进 EXE **同目录**。
2. 直接双击 `造价驻场工作台.exe`。
3. 启动器在打开窗口前自动检测：版本号更高 → 原子替换程序 → 写入 `data/version.json` → 删除更新包。
4. 打开后标题栏会显示新版本，数据原封不动。

### 方式 B：手动更新（窗口内触发）

1. 把 `update_GX1.0.0.2.zip` 放进 EXE 同目录。
2. 打开 EXE → 右上角「自动备份设置」→ 底部「检查更新」。
3. 发现更新包 → 确认应用 → 提示重启程序。
4. 重启后即完成。

---

## 七、回滚与故障恢复

- **更新失败**：EXE 会保留旧程序备份 `cost-workbench.html.bak.时间戳`，若主程序已损坏会自动从备份恢复，旧版仍可启动。
- **新版想退回旧版**：把 `cost-workbench.html.bak.时间戳` 重命名为 `cost-workbench.html` 覆盖即可；`data/` 下数据不受影响。
- **更新包误删**：自动更新成功后更新包会被删除；手动更新前会提示确认，不会误删。

---

## 八、数据安全须知

1. 更新**只替换程序文件**，用户数据始终在 `data/user-data.json` 与 `data/config.json`，不会被覆盖。
2. 重大操作前，建议用户在 EXE 内「自动备份设置」→ 指定备份文件夹 →「立即备份一次」。
3. 浏览器预览与 EXE 数据不互通；正式驻场一律用 EXE 版。
4. 发版前务必对新 `cost-workbench.html` 跑校验（见 `verify_html_js.py`），确保无语法/引用错误。

---

## 附：常见问答

**Q：不打包 EXE，只给用户更新包行不行？**
可以。EXE 本身很少改，更新包只含 HTML 即可。

**Q：用户有多个子项目数据，更新会混吗？**
不会。数据是同一份 `data/user-data.json`，与程序版本无关。

**Q：版本号填错会怎样？**
若更新包版本 ≤ 本地版本，EXE 启动时会自动跳过，不重复应用。

**Q：可以同时放多个更新包吗？**
可以，EXE 只会取**版本号最高**的那个应用一次。
